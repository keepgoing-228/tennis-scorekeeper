# i18n Internationalization Design

## Overview

Add multi-language support to the Tennis Scorekeeper PWA, enabling English, Mandarin Chinese, and Japanese users to use the app in their preferred language.

## Decisions

| Aspect | Decision | Rationale |
|--------|----------|-----------|
| Library | react-i18next + i18next-browser-languagedetector | Industry standard, battle-tested, great interpolation support |
| Languages | English (default), Chinese (zh), Japanese (ja) | Target user base; small fixed set |
| Translation scope | UI chrome only | Tennis scoring terms (Deuce, Love, Ace, etc.) stay in English — matches real-world usage |
| File structure | Flat JSON, one file per language | ~60 strings total, nesting unnecessary |
| Language detection | Auto-detect from `navigator.language`, manual override | Best of both: zero-config for most users, flexibility for the rest |
| Switcher UI | Segmented pill control at bottom of NewMatch page | Clean, unobtrusive, only on the setup page |
| Persistence | localStorage via i18next-browser-languagedetector (key: `i18nextLng`) | No DB schema changes, persists across sessions |

## Dependencies

New npm packages:
- `i18next`
- `react-i18next`
- `i18next-browser-languagedetector`

## File Structure

```
src/i18n/
├── index.ts              # i18next initialization & config
└── locales/
    ├── en.json           # English (default/fallback)
    ├── zh.json           # Mandarin Chinese
    └── ja.json           # Japanese
```

## i18next Configuration

`src/i18n/index.ts`:
- Initialize i18next with `initReactI18next` plugin
- Register `LanguageDetector` for auto-detection
- Import all 3 locale JSON files statically (no lazy loading — files are small)
- Set `fallbackLng: 'en'`
- Set `interpolation.escapeValue: false` (React handles escaping)
- Detection order: localStorage → navigator

Import `src/i18n/index.ts` in `main.tsx` before rendering `<App />`.

## Component Integration

All 5 UI files are updated:

### Pattern for inline strings

```tsx
// Before
<button>Start Match</button>

// After
const { t } = useTranslation();
<button>{t('startMatch')}</button>
```

### Pattern for constant arrays

Constants like `WINNER_REASONS`, `ERROR_REASONS`, and `STAT_LABELS` change from hardcoded `label` strings to translation keys:

```tsx
// Before
const WINNER_REASONS = [
  { value: "ACE", label: "Ace" },
];

// After
const WINNER_REASONS = [
  { value: "ACE", labelKey: "ace" },
];
// In JSX: t(reason.labelKey)
```

### Files affected

| File | Changes |
|------|---------|
| `src/ui/pages/NewMatch.tsx` | ~12 strings → `t()` calls, add language switcher pill control |
| `src/ui/pages/Scoring.tsx` | ~7 strings → `t()` calls including `window.confirm()` |
| `src/ui/pages/MatchHistory.tsx` | ~18 strings → `t()` calls, constant arrays use `labelKey` |
| `src/ui/components/Scoreboard.tsx` | ~3 strings → `t()` calls |
| `src/ui/components/AnnotationBar.tsx` | Constant arrays use `labelKey` pattern |

## Language Switcher Component

A `LanguageSwitcher` component rendered at the bottom of `NewMatch.tsx`:

- Segmented pill control with 3 options: `EN` | `中文` | `日本語`
- Calls `i18n.changeLanguage(lng)` on click
- Active language is visually highlighted
- Styled with Tailwind CSS to match existing app design
- Positioned below the "Start Match" button and "Match History" link

## What Is NOT Translated

- Tennis scoring terms: Love, 15, 30, 40, Deuce, Advantage, Game, Set, Match
- Tiebreak scoring (numeric)
- Player names entered by the user
- The `value` fields in annotation constants (ACE, WINNER, DOUBLE_FAULT, etc.) — these are internal identifiers
